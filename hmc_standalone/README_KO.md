# 독립 HMC 차량 모델

**현재 전체 계산은 roll·pitch 응답 개선을 위해 일시 중단했습니다. 기존 결과는 수정 전 모델의 참고 결과입니다.**

사용자가 제공한 CarSim 실행 Echo, HMC 차량·마모 타이어 데이터, 활성 Simulink 댐퍼 모델을 이용해 새로 구현한 독립 모델입니다. CarSim 또는 TNO DLL을 호출하지 않습니다. CarSim/MF-Swift 내부 엔진과 동일한 코드가 아니며, 독립 근사 모델로 결과를 구분합니다.

## 실행

이 폴더를 MATLAB Current Folder로 설정합니다. C++17/OpenMP 컴파일러가 있으면 가속 엔진을 빌드합니다.

```matlab
hmc_build_native;
R = run_hmc_standalone('baseline'); % 50km/h, mu=.5, 0deg, 정상 타이어
R = run_hmc_standalone('full');     % 210조건 × 마모5종
```

M-code만 사용하려면 `struct('engine','mcode')`를 두 번째 인자로 줍니다. M-code는 수식 확인용이며 전체 실행은 매우 느립니다. 기본 출력은 코드 폴더의 `results_new_210`이며 `output_dir` 옵션으로 변경합니다.

속도6종(50~100km/h), mu5종(.9,.8,.7,.6,.5), 전륜 조향각7종(0:.5:3deg), 마모5종을 사용합니다. 네 코너 CDC950mA, spring mode2(normal), 초기 vy/r 격자61×121, 시간간격.001s, 관측5/10s, 마지막1s 복귀 판정입니다. 신체·휠의 숨은 초기상태는 독립 모델의 검증된 정상선회점에서 가져오고 초기 vy/r만 변경합니다.

## 실제 실행 데이터 반영

- 실행 Echo의 스프링은30,790N/m 선형입니다. 원래 assembly PAR의 다른 선도보다 실제 실행 Echo를 우선합니다.
- 순정 중력9.80665m/s², sprung mass1967.686kg, 전체2218.042kg, 측정 관성·비현가질량을 가져옵니다.
- 정상/전륜25K/전륜50K/후륜25K/후륜50K 타이어5개를 별도로 유지합니다.
- MF6.2 순수/복합 슬립, 캠버·압력, 얼라인먼트 토크 및 구름저항을 구현합니다. 유효 구름반경은 자유반경과 다릅니다.
- 실제 데이터 파일의 TYRESIDE Left 규약을 유지하며 휠 좌표에서 캠버·토우 부호를 변환합니다.
- CDC는 활성 Simulink에 내장된18×17 정수 선도, 입력 포화·쌍선형 보간을 유지합니다. 현 CarSim 입출력의 모션비는1입니다.
- 속도는 고정 상태가 아니라 PI 제어로 유지합니다. KP=.14s/m, KI=.16/m이므로 오차는 m/s입니다. 정밀한 CarSim 내부 제어 구현 대신 제한 전력 명령과 명시적 antiwindup을 사용합니다.

## 범위와 한계

34상태는 vy,r,차체 heave/roll/pitch, 네 unsprung 수직변위/속도, 휠 회전, 타이어 슬립 완화 상태, 종속도와 PI 적분 상태 등을 포함합니다. 측정된 현가 운동학·컴플라이언스 표를 사용하지만 다물체의 모든 구속·jacking을 복제하지는 않습니다. SPLINE 표는 명시적 선형 구간 보간을 사용합니다. MF-Swift 벨트/회전슬립 내부 상태는 제공된 계수만으로 복제하지 않습니다. 상세 가정은 `hmc_vehicle_model.m`의 `Q.assumptions`에 보존합니다.

`hmc_handling_reference.m`은 제공된 CarSim 자동화 코드의 기존 MF 2×2 Jacobian 기준 H를 그대로 계산합니다. 이 판정 정책의 기존 MF 계수와 실제 차량 힘 계산용 MF6.2 계수는 역할이 다릅니다. H 밖의 초기점은 미계산입니다. `hmc_classify.m`은 원본 CarSim 자동화 코드의 출력 수준 물리 제약·마지막1초 복귀·H 이탈 판정을 따릅니다. 주 결과 `final`에는 yaw/ay guard를 자동 교차하지 않으며 `guarded_final`에 별도로 저장합니다.

MAT 변수 `RESEARCH2D`의 `CASE{1}`~`{5}`에 각 마모의 정상선회점, 기준 H, 원시 진단, 마스크와 셀 중심점 결과가 있습니다. `final`은 유한시간 H 유지 복귀 표본이며 증명된 불변집합/점근 안정영역이 아닙니다. 영역 이동, 볼록껍질 채우기 또는 CarSim 점 수에 맞춘 제약은 사용하지 않습니다.

코드의 M-code/C++ 일치는 수치 구현 검증이고, CarSim 데이터와의 일치는 별도로 비교합니다. `compare_reference.py`는 제공된 실제 CarSim MAT에서 추출한 마스크와 새 결과를 좌표 이동 없이 비교합니다. 동일 결과를 보장한다는 의미가 아닙니다.

## 실제 기준 비교 결과

제공된 정상타이어50km/h·mu=.5·0deg에서 H227점이 동일했고,5/10초 final은 CarSim200점·독립모델201점으로 한 점 차이였습니다. 공통200점, 합집합201점으로 Jaccard99.50%, 전체H내판정일치는226/227(99.56%)입니다. guarded_final196점, recoverable227점은 좌표까지 일치했습니다. 셀 면적은CarSim.3925, 독립모델.395입니다. 이 비교는 해당한조건에 한정되며 다른210조건 전체의 CarSim재현을 보장하지 않습니다. 차이를 없애기 위한 영역 제약이나 계수피팅은 하지 않았습니다.

수치 검증은 독립M-code/C++ RHS·짧은RK4 일치,20,001개10초Native표본에 대한 독립M-code 판정 일치,dt.0005→.00025의10초상태차이8.51e-9(scaled)를 확인했습니다. 전체10초 M-code 적분은 실행하지 않았습니다.

실제 전체 실행은 CarSim 외부 적분과 같은 dt=.001s를 사용합니다. 기준 조건에서 dt=.0005s와 H·모든 판정 마스크·통과 셀 마스크가 모두 일치했으며 시간은98.24초→48.56초였습니다.

공개 결과 폴더는 `../results/hmc_standalone_public`입니다. 공개MAT에서는 원본 차량·타이어 계수 데이터와 로컬 파일 경로를 제거하고 계산결과·데이터 체크섬을 저장합니다. 재실행 입력데이터는 사용자가 보유한 파일로 로컬에서 준비합니다. Pitch·roll의 CarSim시간응답은 현재 미검증이며 정상pitch값도차이가있습니다.
