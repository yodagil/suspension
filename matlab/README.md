# MATLAB 안정영역 210조건 계산 코드

ZIP을 풀고 MATLAB에서 `matlab` 폴더의 `run_210_conditions.m`을 실행하세요. 결과는 `results_mcode`에 `stable_point_80kph_0.9mu_0deg.mat` 같은 이름으로 저장됩니다. 진입 파일만 받지 말고 같은 폴더의 의존 함수 `.m` 파일 5개도 함께 두세요. MATLAB용 진입점은 C++ 없이 `engine='mcode'`로 실행합니다. MATLAB의 Java VM을 사용한 파일 해시 계산이 필요합니다.

속도 50·60·70·80·90·100 km/h, μ 0.9·0.8·0.7·0.6·0.5, 전륜 휠 조향각 0·0.5·1·1.5·2·2.5·3°의 210조합입니다. 바퀴별 조향은 `[angle angle 0 0]`이며 마모 5종, 마모별 초기조건 39,401개(41×31×31), 관측 5초, Ts=0.01초, RK4 하위 적분 20회를 유지합니다. 순수 MATLAB 경로는 현재 클라우드의 GNU Octave/C++ 가속 경로보다 훨씬 느립니다. 실제 클라우드 가속기의 `native_accel.cpp`와 빌드 스크립트도 포함했습니다. 수치 방정식과 격자·판정 알고리즘은 같습니다. μ=0.9의 80 km/h·2° 결과는 사용자 기준 MAT의 5종 전체와 대조했습니다.

노면 μ는 기준값 0.9에 대한 상대 배율 `scale=mu/0.9`로 종·횡 타이어 Magic Formula 진폭 `Dx`, `Dy`에 반영합니다. μ=0.9이면 배율 1이므로 첫 번째 원본 코드의 타이어 보정을 유지하고, μ=0.6이면 배율은 2/3입니다. 요율 한계는 `0.85*mu*g/ux`, 횡가속도 한계는 `mu*g`이며 LTR 한계는 1로 유지합니다. 원본 횡력 오프셋 `SVy`는 스케일하지 않으므로 실제 모든 하중·마모에서 타이어 피크 계수가 정확히 μ가 되는 절대 정규화는 아닙니다.

배포 사본의 `run_stability_sweep.m`은 MATLAB 경로의 `run_info.reason_semantics` 표기를 실제 설정에 맞게 고쳤습니다(`early_exit_on_unstable=false` → `full_horizon_accumulated`). 이 수정은 진단 문자열만 바꾸며 운동방정식·타이어 힘·적분·안정 판정·영역 계산은 바꾸지 않습니다. 나머지 네 `.m` 함수와 C++ 소스는 실행 중인 고정 코드 사본과 바이트가 같습니다. 공개 결과를 이 사본의 캐시로 혼용하지 마세요. 코드 해시가 다르면 저장 결과 재사용 검증이 거부합니다.
